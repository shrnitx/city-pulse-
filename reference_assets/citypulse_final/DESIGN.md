## Brand & Style

This design system establishes a high-fidelity civic intelligence platform designed for municipal administrators, urban planners, public operations leads, and active civic stakeholders. The brand ethos prioritizes institutional integrity, procedural transparency, and operational clarity.

The visual style merges **Corporate / Modern** precision with **Minimalist** clarity:
- **Tone:** Authoritative yet accessible, systematic, transparent, and resilient under critical data loads.
- **Aesthetic Tenets:** Information-dense layouts without visual noise, high-legibility typographic hierarchies, sharp structural framing, and deliberate functional color assignment. Frivolous decorative treatments, novelty skeuomorphism, and exaggerated micro-interactions are rejected in favor of predictable spatial geometry and low-latency readability.
- **Emotional Resonance:** Users should feel composure, complete situational awareness, and sovereign trust in the state of all tracked civic assets, incidents, and infrastructure metrics.

## Colors

The palette employs deep structural slates paired with purposeful operational accents, engineered for data density, contrast compliance, and rapid status parsing.

- **Primary (`#0D9488` / Deep Civic Teal):** Applied to primary calls-to-action, active navigational anchors, verified focal indicators, and interactive links. Provides an established, grounded civic identity distinct from generic SaaS blue.
- **Secondary (`#0F172A` / Civic Dark Slate):** Delivers bedrock structural grounding. Applied to high-emphasis headers, side navigation chrome, top command bars, and baseline text hierarchies. Secondary interactive tier (`#1E293B`) serves as nested container strokes and secondary actions.
- **Tertiary (`#06B6D4` / Tactical Cyan):** Reserved for telemetry metrics, telemetry charts, focus rings, and high-priority spatial wayfinding pins.
- **Neutral (`#64748B` / Cool Slate):** Governs secondary textual content, icon states, divider lines, and inactive toggle surfaces. Surface neutrals transition from light canvas slate (`#F8FAFC`) through container neutral (`#F1F5F9`) up to pure canvas white (`#FFFFFF`).
- **Semantic & State Signals:**
  - **Resolution / Verified:** Emerald (`#10B981`) indicates resolved issues, validated reports, active services, and verified public records.
  - **Active Review / Triage:** Amber (`#F59E0B`) flags pending review, in-flight work orders, escalated dispatches, or scheduled maintenance.
  - **Critical Alert:** Crimson (`#EF4444`) isolates system outages, emergency dispatches, and policy threshold breaches.

## Typography

The typographic engine uses a tripartite structural hierarchy:
1. **Headlines (`Plus Jakarta Sans`):** Clean, geometric, authoritative sans-serif featuring tight tracking and balanced ascenders to structure high-density administrative views.
2. **Body & Controls (`Inter`):** Systematic neutral sans-serif designed for legibility at standard operational scale (12px–16px), optimized for fast scanning of municipal tickets, logs, and telemetry.
3. **Data & Identifiers (`JetBrains Mono`):** Applied exclusively to municipal ordinance codes, parcel IDs, GPS coordinates, commit hashes, pull requests, and telemetry timestamps.

### Usage Standards
- Display and `headline-lg` sizes must adopt negative letter spacing to avoid horizontal bloat in wide-viewport monitoring consoles.
- All numbers within tables, ledger components, and live resource graphs must use tabular lining figures (`font-variant-numeric: tabular-nums`).
- Code labels (`code-sm`, `code-md`) are always set in uppercase when rendering short ticket IDs or parcel boundaries (e.g., `ORD-2024-91B`).

## Layout & Spacing

This design system uses an **8-point mathematical grid** with a 4-point subgrid for micro-alignments (chips, badges, and inline status icons).

### Layout Grid Architecture
- **Desktop (≥ 1280px):** 12-column fluid grid, 2rem outer page margin, 1.5rem gutters. Max content bounding box spans 1440px for standard forms and reports; full-bleed 100% viewport width enabled exclusively for geographic mapping and live dispatch operations.
- **Tablet (768px – 1279px):** 8-column responsive grid, 1.5rem outer canvas margin, 1.25rem gutters. Data side-panels dock into an off-canvas drawer or stack below core visualization modules.
- **Mobile (< 768px):** 4-column single-stream grid, 1rem margin, 1rem gutter. Multi-metric summary cards collapse into single-column vertical stacks.

### Internal Spacing Cadence
- Element padding inside atomic inputs and controls remains locked to `space-sm` (vertical) and `space-md` (horizontal).
- Structural card padding is uniform at `space-lg` (24px) for desktop and `space-base` (16px) for mobile.
- Section vertical flow leverages `space-xl` (32px) to preserve cognitive breathing room across content-dense dashboards.

## Elevation & Depth

Visual hierarchy uses **low-contrast structural outlines** alongside **tonal surface layering** rather than heavy drop shadows. This preserves crispness on utility-grade municipal screens and low-spec field displays.

### Layering Model
- **Level 0 (Canvas):** `#F8FAFC` base system backdrop.
- **Level 1 (Card / Panel Surface):** `#FFFFFF` surfaces defined by a 1px border of `#E2E8F0` (`border-slate-200`). A subtle ambient drop shadow (`0 1px 2px 0 rgba(15, 23, 42, 0.04)`) separates surface from canvas.
- **Level 2 (Dropdowns / Flyouts):** `#FFFFFF` elevated container with 1px border of `#CBD5E1` and ambient shadow (`0 4px 6px -1px rgba(15, 23, 42, 0.08), 0 2px 4px -2px rgba(15, 23, 42, 0.04)`).
- **Level 3 (Modal / Critical Dialog):** `#FFFFFF` surface accompanied by a 40% backdrop scrim in `#0F172A` with blur (`backdrop-filter: blur(2px)`). Depth delineated with `0 10px 15px -3px rgba(15, 23, 42, 0.12), 0 4px 6px -4px rgba(15, 23, 42, 0.06)`.

Gradients and decorative glows are prohibited on interface surfaces. Visual emphasis must always be established through contrast differentials, semantic border accents, and background saturation steps.

## Shapes

The design system implements a **Soft (Level 1)** geometric standard. This delivers a measured balance of administrative rigor and modern digital ergonomics.

- **Base Radius (0.25rem / 4px):** Standard for form inputs, utility action buttons, inline code blocks, tables, and status tags.
- **Intermediate Radius (`rounded-lg`, 0.5rem / 8px):** Structural cards, metric tiles, modal containers, and docked operational panels.
- **Large Radius (`rounded-xl`, 0.75rem / 12px):** Root dashboard containers and standalone public-facing informational views.
- **Circular (`rounded-full`):** Reserved strictly for avatar profiles, radio dot indicators, and status ping notifications. Rounded pill buttons are prohibited for core administrative actions to maintain a consistent architectural silhouette.

## Components

### Buttons
- **Primary:** Background `#0D9488`, text `#FFFFFF`, font-weight 600. Hover: `#0F766E`. Active: `#115E59`. Focus: 2px offset ring in `#06B6D4`. Padding: `0.5rem 1rem`. Border radius: 4px (`rounded`).
- **Secondary:** Background `#FFFFFF`, text `#0F172A`, 1px solid border `#CBD5E1`. Hover: `#F1F5F9`. Active: `#E2E8F0`.
- **Destructive:** Background `#EF4444`, text `#FFFFFF`. Hover: `#DC2626`.
- **Ghost / Utility:** Transparent background, text `#475569`, hover background `#F1F5F9`.

### Chips & Status Badges
- Non-pill structure (border-radius 4px). Small padding (`0.125rem 0.5rem`), font `label-sm` or `code-sm`.
- **Verified / Resolved:** Background `#ECFDF5`, text `#065F46`, border 1px solid `#A7F3D0`. Includes a 6px green bullet.
- **Active Review:** Background `#FFFBEB`, text `#92400E`, border 1px solid `#FDE68A`.
- **Critical / Urgent:** Background `#FEF2F2`, text `#991B1B`, border 1px solid `#FECACA`.
- **Neutral / Draft:** Background `#F1F5F9`, text `#334155`, border 1px solid `#CBD5E1`.

### Cards & Data Panels
- Background `#FFFFFF`, 1px border `#E2E8F0`, border-radius 8px.
- Internal headers include an explicit bottom border separating metadata from data content. No high-elevation shadows. Metric cards display clear label, numeric value in `Plus Jakarta Sans`, and a delta tracker badge.

### Form Inputs
- Height 36px (dense) or 40px (default). Background `#FFFFFF`, border 1px solid `#CBD5E1`, text `#0F172A`, placeholder `#94A3B8`.
- Focus state: border color `#0D9488`, box-shadow `0 0 0 1px #0D9488`.
- Error state: border color `#EF4444`, message displayed in `body-sm` with crimson tint.

### Checkboxes & Radio Buttons
- Checkbox: 16px square, 3px border radius. Unchecked: border `#94A3B8`, background `#FFFFFF`. Checked: background `#0D9488`, white SVG check icon.
- Radio: 16px circle. Checked: background `#FFFFFF`, border 5px solid `#0D9488`.

### Lists & Activity Feeds
- Zebra-striping disabled; items partitioned by clean 1px `#F1F5F9` borders.
- Hover state: `#F8FAFC` background shift across the entire record row. Monospace IDs anchored to left edge (`JetBrains Mono`).

### Structured Audit Timelines
- Vertical 2px line in `#E2E8F0` positioned left of event text.
- Timeline nodes rendered as 10px circular nodes colored semantically (Emerald for resolution, Amber for triage, Slate for standard state changes).
- Each entry includes a precise timestamp in `code-sm` (`#64748B`), author role, and immutable audit trace hash.
